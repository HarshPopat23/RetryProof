4. Documentation


      

        
Why RetryProof Exists

        

          In automated workflows (e.g. n8n agents calling tools), network timeouts or crashes often occur
          after an external action (such as creating an issue) has already succeeded remotely.
          A blind retry sends the creation request again, resulting in duplicate records.
        

      


      

        
How It Works

        
    
          
  1. Persist Intent First: Intent is saved in durable SQLite storage before dispatching any request.
    2. 
          
  2. Single Dispatch: Transactional ownership ensures only one dispatch per operation key.
    3. 
          
  3. Evidence Verification: If interrupted, RetryProof performs read checks before attempting any action.
    4. 
          
  4. Resume vs. Pause: If evidence is found, it adopts the record and continues downstream. If evidence is missing or uncertain, it safely pauses instead of guessing.
    5. 
        

      


      

        
MCP Tool Reference

        

          
            

              Tool
              Description
            

          
          
            

              rp_start_workflow
              Registers a stable task ID, dispatches and verifies the issue, then dispatches and verifies the tracking record.
            

            

              rp_resume_workflow
              Inspects external evidence and continues an interrupted or paused workflow without blindly repeating a previously dispatched write.
            

            

              rp_get_receipt
              Retrieves the durable SQLite audit ledger and chronological verification events.
            

            

              rp_discover_capabilities
              Lists downstream tools available across connected issue and tracking providers.
            

          
        

      


      

        
Status Codes

        

          completed: All steps succeeded and were verified.

          paused: Uncertain outcome; write was not repeated; requires inspection or resume.

          in_flight: Dispatch claimed and actively executing.

          unknown: No conclusive evidence found yet; duplicate write prohibited.
