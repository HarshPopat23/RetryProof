# Participant submission checklist

The supplied guidebook requires the following [S00](SOURCES.md#s00). The ZIP supplies code and documentation; account actions and publishing are still yours to complete.

- [ ] Choose project name RetryProof, Developer Tools track, and original product n8n.
- [ ] Create a public GitHub repository and upload this project, including the README and lockfile.
- [ ] Run `npm ci` and `npm run verify` on your machine.
- [ ] Test tools in NitroStudio.
- [ ] Configure a real GitHub test repository if desired; disclose whether the final demo uses sandbox or real data.
- [ ] Deploy on NitroCloud after confirming Node/subprocess/persistent-storage support.
- [ ] Test authenticated discovery, a complete handoff and restart recovery at the live URL.
- [ ] Record an actual working demo video using the provided script.
- [ ] Publish the mandatory LinkedIn post and tag the official MCP to the Moon handle plus any organizer-required community handle.
- [ ] Supply project explanation, repository URL, video URL, live demo URL and LinkedIn URL in the official portal.
- [ ] Confirm current deadline, team eligibility and portal URL through organizer announcements.
- [ ] Review carefully before submitting: the guidebook says submissions lock after submission.

Do not claim that n8n itself was patched, that synthetic sandbox data is production evidence, that MCP alone supplies exactly-once behavior, or that the project is the first recovery tool. The evidence is stronger when the claim matches what runs.
