# Judge brief

**Project:** RetryProof. **Track:** Developer Tools. **Original product:** n8n. **Workflow improved:** recovery of a multi-service issue handoff.

## Problem and result

An agent can observe failure while an external write has already succeeded. Blind retries can duplicate records, while blindly moving ahead can lose the cross-system link. RetryProof persists intent before dispatch, verifies the external effect, and resumes only the supported remaining work.

The visible before/after is small: the unsafe baseline creates two records for one task; the protected run creates one issue and one linked tracking record, survives gateway recreation, and preserves a human's edit. A missing-evidence run stays paused instead of inventing success. The baseline and protected counts are generated by `npm run demo`, not hand-authored performance claims.

## Engineering points worth inspecting

* Dispatch ownership is claimed transactionally before the external call, rather than deduplicating only after a response arrives.
* A stale read is not treated as proof that nothing happened.
* A concurrent worker's verified receipt cannot be downgraded by a late failure.
* Identity includes destination and source linkage, not just matching titles.
* A new intentional task with the same text is not collapsed into an older one.
* Provider text cannot change the deterministic recovery policy.
* Tests exercise two gateway OS processes and a SIGKILL in the post-commit, pre-response window.

## Honest differentiation

MCP proxies, idempotency and evidence-based recovery already have prior art [S04](SOURCES.md#s04), [S14](SOURCES.md#s14), [S15](SOURCES.md#s15). The contribution is an inspectable implementation and demonstrated behavior for a precise crash/uncertainty boundary, not a claim that nobody has noticed retries before.

## Evidence boundary

Use the [experiment guide](EXPERIMENTS.md) as the review entry point. Fresh keyless runs save independent provider inventories and require an actual remote HTTP 401/403 plus a successful authenticated control. They distinguish dashboard reconnect (experiment 7), a separate gateway SIGKILL and controlled model-output rejection checks.

The [historical participant receipts](../experiments/README.md) identify live GitHub issues and Groq responses. Their reported 10 PASS results have narrower evidence than the original summary suggested: no full inventory history, no raw authentication status and one injection input handled literally. They are retained as supplied, not silently treated as new runs.

No production incident rate, general injection protection, LLM success rate or latency improvement is claimed. n8n UI import/run, NitroStudio UI operation, Docker construction and cloud deployment are not represented as completed. The local crash supplement is not complete host-loss or cloud-replica recovery.
